## Highlights

Correctness and reliability fixes across `KafkaService`, `PlanManager`, `ApplyManager`, and `StateManager`. No new features or API surface changes.

## Fixed

- **Resource leak**: `FileWriter` in `PlanManager.writePlanToFile` is now closed via try-with-resources, preventing a file descriptor leak when serialization fails.
- **Thread interrupt swallowed**: All 10 `InterruptedException` catch sites in `KafkaService` now restore the interrupt flag via `Thread.currentThread().interrupt()` before rethrowing, preserving cooperative cancellation for callers.
- **Double AdminClient**: `updateTopicReplication` now reuses the existing `AdminClient` for the topic description lookup instead of opening a second connection.
- **Invalid reassignment payload**: `updateTopicReplication` validates that the replication factor is non-null and `>= 1` upfront, before entering the reassignment loop.
- **Spurious Kafka API calls**: `ApplyManager` now skips `NO_CHANGE` topic config plans, eliminating unnecessary `incrementalAlterConfigs` calls on every apply for large clusters.
- **IndexOutOfBoundsException**: `PlanManager` now guards against an empty partition list when inspecting an existing topic, and throws a `ValidationException` with a helpful message instead of a bare exception.
- **NoSuchElementException on missing defaults**: `StateManager.generateTopicsState` now throws a `ValidationException` with context when topic partition/replication defaults are absent, instead of a bare `NoSuchElementException`.
- Fix `addTopicPartition` guard: `<= 1` corrected to `< 1`.
- Fix typos in error messages: `increate` → `increase`, `enougth` → `enough`, `newReasignement` → `newReassignment`.
- Make static loggers `final` in `PlanManager`, `KafkaService`, and `StateManager`.
